Ship a static marketing site plus an install page. Push to `main` when the checks below pass.

## Hard requirements

1. **Plain static site.** No frameworks, no bundler, no npm, no CDN JavaScript. Hand-written
   HTML + CSS, served exactly as committed. Minimal or zero JS; inline `<script>` only for
   copy-to-clipboard buttons.
2. **Files to create:**
   - `index.html` — landing page for **TalosBot** / Talos HQ.
   - `install/index.html` — the install page.
   - `assets/styles.css` (shared stylesheet), `favicon.svg` or `.ico`.
   - `CNAME` containing exactly `talosbot.ai` and a trailing newline.
   - `.nojekyll` (empty file).
   - `.github/workflows/pages.yml` — GitHub Actions Pages deploy: `actions/configure-pages@v5`,
     `actions/upload-pages-artifact@v3` with `path: .`, `actions/deploy-pages@v4`; triggers on
     push to `main` and `workflow_dispatch`; `permissions: {contents: read, pages: write,
     id-token: write}`; `concurrency: {group: pages, cancel-in-progress: false}`. Because the
     artifact is the repo root, exclude `.git`, `.github`, and any docs you add from the
     upload — simplest correct approach: build a `_site/` staging directory in a prior step and
     upload that.
   - `docs/install-evidence.md` — the proof described in requirement 4.
3. **The install page installs exactly two real things, and both must work today:**

   - **clud** — a Rust CLI wrapping Claude Code and Codex. Real installer, verified:
     `curl -fsSL https://raw.githubusercontent.com/talos-hq/clud/main/install.sh | sh`
     (it bootstraps `uv` if missing, then `uv tool install clud`). Support
     `CLUD_VERSION=<ver>` pinning. Published Pages catalog/manifest lives at
     `https://talos-hq.github.io/clud/install/manifest.json` — you may link it.
   - **The agent** — repo `github.com/talos-hq/hermes-slim`, a fork of `hermes-agent`
     (`pyproject` name `hermes-agent`, version `0.0.0`, one draft release `v0.1.0`). It has
     **no installer of its own**; its README points at the *upstream*
     `https://hermes-agent.nousresearch.com/install.sh`, which is a different product. Do NOT
     present the upstream installer as if it installed this fork. Determine the real working
     path from this fork and publish only what you verified.

4. **The installer must be proven, not asserted.** For every install one-liner that appears on
   the page, actually run it in a throwaway environment and confirm the entrypoint executes:
   - isolate with `UV_TOOL_DIR=/tmp/sitecheck/tools UV_TOOL_BIN_DIR=/tmp/sitecheck/bin`
     (and/or a fresh `uv venv`) so the real user environment is untouched;
   - run the installed binary's `--version` (or `--help`) and capture the output;
   - write `docs/install-evidence.md` with: the exact command, the observed stdout/stderr tail,
     the version reported, the date, and any prerequisite (uv, python, rust) the command needs;
   - state honestly in that document anything you could NOT verify and why. If the fork cannot
     be installed cleanly, offer the verified clone-and-activate path
     (`git clone … && cd hermes-slim && source ./activate`) instead — but only after running it.
   - If a command fails, either fix the command or drop it from the page. An unverified or
     previously-broken command must not ship.

5. **Honesty on copy.** No invented features, benchmarks, customer logos, testimonial quotes, or
   version numbers. Only claims traceable to the repos listed above. Product one-liners you may
   use (these are the repos' own descriptions):
   - clud: "Claude & Codex CLI, with safety 3rd and God Mode always."
   - agent: "The agent that grows with you."
   TalosBot is described as the Talos HQ agent/product line — do not attribute specific
   capabilities to it that the two repos do not support.

6. **Design.** Dark, modern, high-contrast, technical. System font stack. Responsive down to
   360px. Accessible: real landmarks, `<h1>` per page, focus states, `prefers-reduced-motion`
   respected, tap targets ≥44px. The install page needs, per product: the one-liner in a
   copy-to-clipboard block, a short "what it does", prerequisites, and a pin-version example.
   Include a `<link rel="canonical">` on both pages and an OG/Twitter meta set that does not
   reference images that don't exist.

7. **Verify before pushing:**
   - `python3 -m http.server` (or `uv run python -m http.server`) on the staging dir and fetch
     both pages with `curl -sS -o /dev/null -w '%{http_code}'` — expect 200.
   - Check every internal link and asset path resolves (no 404 for `.css`, favicon, `install/`).
   - `grep` the built HTML for `localhost`, `127.0.0.1`, `TODO`, and placeholder text; all must
     be absent.
   - Validate the workflow YAML parses (`python3 -c "import yaml,sys;yaml.safe_load(open('.github/workflows/pages.yml'))"`).
